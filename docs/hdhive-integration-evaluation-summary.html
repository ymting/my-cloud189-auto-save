HDHive（影巢）集成方案评估与总结报告

本报告对项目中存在的两份 HDHive 集成方案文档——《HDHive（影巢）资源搜索与解锁集成可行性报告》（业务可行性侧重）与《HDHive OpenAPI 接入设计方案》（技术实现侧重）进行综合评估与对比总结，提炼出核心结论、技术路线选择及落地开发建议。

0. 影巢应用凭证配置

凭证获取说明

影巢 OpenAPI 采用 X-API-Key Header 鉴权模式。每个部署者需要自行申请凭证：

  1. 访问影巢开放平台，注册开发者应用
  2. 获取应用的 Client ID 和 Secret
  3. 在系统设置页面填入凭证信息

鉴权方式

GET /api/open/resources/:type/:tmdb_id HTTP/1.1
Host: api.hdhive.com
X-API-Key: <your_api_key>

系统配置入口（规划）

配置项 说明
hdhive.enabled 是否启用影巢集成
hdhive.apiKey 你的影巢 API Key
hdhive.baseUrl 影巢 API 地址（默认 https://api.hdhive.com）

⚠️ 重要：凭证属于敏感信息，请勿提交到公开代码仓库。建议通过环境变量或加密配置文件存储。

统一的架构共识

两份方案在底层技术选型上达成了一致： 1. 统一鉴权：使用影巢的 OpenAPI，在 HTTP Headers 中附带用户个人的 X-API-Key。 2. TMDB 协同：直接复用系统已有的 TMDBService 模糊搜索出精确的 TMDB ID，再用 TMDB ID 去影巢接口精准匹配资源，避开影巢本身模糊搜索的频率限制和反爬。 3. 网盘分类：前端按 115、123、夸克、阿里、百度 5 大主流网盘进行选项卡过滤。 4. 一键转存：解锁原链后，不只提供“复制链接”按钮，而是自动填充系统新建任务表单，实现自动化闭环。

2. 方案深度评估：优势、风险与应对策略

2.1 核心优势 (Strengths)

  • 开发成本极低：由于系统已内置 TMDB 服务、任务创建系统和 CAS 模块，整个集成无需引入复杂的依赖，只需进行 SDK 接口对接与前端 UI 绘制，预计总工期在 6.5 天 左右。
  • 业务粘性高：打通了“找资源-转存”的最后一公里，用户无需在浏览器和转存系统间频繁复制切换。

2.2 潜在风险 (Risks) & 优化建议 (Optimizations)

风险 1: 真实积分损耗与误触 (Critical)

影巢的部分优质资源解锁需要消耗用户的真实积分。如果前端没有足够强的警示，或者由于代码逻辑重试导致重复扣分，会引发严重的用户投诉。 - 应对策略： 1. 前端强警示：解锁非 0 积分资源时，必须弹出红字强提醒的二次确认弹窗，并展示解锁后将剩余的积分预估。 2. 后端去重与防抖：同一 resourceId 在短时间内（如 10 分钟内）的解锁请求，后端应做内存级排队与防抖，避免网络抖动导致浏览器重复发送 POST 请求引发二次扣分。

2.3 接口稳定性与熔断机制 (High)

影巢作为第三方社区站点，存在临时维护、接口升级、甚至 IP 被封禁的风险。 - 应对策略： 1. 优雅降级：当影巢接口返回 502/504 等超时错误时，前端不应崩溃，而是显示“影巢服务器临时维护中，请稍后再试”。 2. 缓存机制：对 GET /api/hdhive/resources 结果在后端进行短时间内存缓存（如 5 分钟），避免用户在不同网盘页签来回切换时重复请求影巢接口。

3. 落地开发建议与实施排期

建议将两份方案合二为一，按照以下里程碑执行落地：

  1. 第一阶段：配置项与鉴权层 (Day 1)
    • 在 SQLite 数据库的设置表增加 hdhive.apiKey。
    • 在系统设置页面增加“影巢配置”表单。
    • 编写 HDHiveSDK.ts，对接 /api/open/ping 与 /api/open/quota 接口，完成连通性与积分查询测试。
  2. 第二阶段：后端资源路由 (Day 2)
    • 实现 GET /api/hdhive/resources（带 5 分钟内存缓存）。
    • 实现 POST /api/hdhive/unlock（带后端去重与防抖锁）。
  3. 第三阶段：前端 UI 与 Tab 选项卡 (Day 3 - Day 4)
    • 在系统顶栏或工具栏增加“影巢搜索”按钮（Indigo 渐变加毛玻璃微动效）。
    • 实现 TMDB 模糊搜索结果展示墙。
    • 实现影视详情页的 5 大网盘分类 Tab 页及资源列表卡片（包含大小、发布人、发布时间、积分标签、失效标签等）。
  4. 第四阶段：解锁与一键转存闭环 (Day 5 - Day 6)
    • 实现积分解锁的二次弹窗确认。
    • 解锁成功后展示“复制链接”与“一键创建任务”，点击“一键创建任务”自动将链接注入新建任务表单并触发解析。
    • 完成联调、异常情况测试（如 Key 过期 401 提示、站点超时提示等）。

4. 结论

综合评估表明，该集成方案在技术与业务上均高度可行，且开发性价比极高。它能让系统从一个单纯的“转存工具”升级为“资源搜索 + 转存 + 整理”的一体化智能媒体管理中心。建议立刻启动第一阶段开发。
